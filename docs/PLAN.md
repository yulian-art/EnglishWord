# 一周协作计划

## 三人分工

| 成员 | 负责模块 | 主要目录 |
| --- | --- | --- |
| A：偏 Go 后端的同学 | C++ 数据库、注册登录、权限、导入、历史统计和打卡 API | backend/src/repositories、后续 services/auth 与 controllers/auth |
| B：React 页面 | 主布局、账号页、词库维护页、导入弹窗、打卡与统计展示 | frontend/src/pages、frontend/src/lib |
| C：学习流程 | C++ 出题、判题、错题持久化与复习；React 背诵页面联调 | backend/src/core、controllers/api、frontend/src/pages/StudyPage.tsx |

同一文件尽量只有一位当前负责人。跨模块先约定请求和响应类型，每天合并，不等最后一天联调。

## 每日目标

| 日期 | 目标 | 验收 |
| --- | --- | --- |

## 后端验收记录（2026-11-14）

完整 C++ 后端在隔离 Linux 环境配置、构建成功，CTest 的 `study_engine`、`database`、`auth`、`progress`、`api_integration` 五项全部通过。HTTP 测试使用真实服务和临时 SQLite，覆盖两账号隔离、公共词库只读、私人词库 CRUD、多释义、BOM/CRLF TSV 与错误行整批回滚、三种模式、并发首答不重复计分、跨轮次掌握状态、历史与错题持久化、上海日期重复打卡及打卡退出。

数据库新增 `002_progress.sql`，由版本 1 自动升级至版本 2，保留旧历史；事务提交失败也不会返回成功。词条编号不再复用，删除并重建不会让旧学习快照关联到新词。登录/切号后旧 Cookie 立即失去权限。重启会丢失临时题目位置，但重新登录后私人词库、成绩、错题及打卡仍在。

新增及完整字段见 [API.md](API.md)，其中历史为 `GET /api/history`，持久化错题复习为 `POST /api/wrong-words/review`（传所选 wordbookId），打卡退出为 `POST /api/auth/logout`（传 `{"checkin":true}`）。示例词库目前为三个词，测试按真实数据验证，不再假定十词。

前端 `App.tsx` 原有合并冲突未处理，已有前端工作和 Git 暂存区未改动；本次没有提交或完成合并。Windows 原生构建、新电脑启动和完整五分钟页面演示尚未验证。
